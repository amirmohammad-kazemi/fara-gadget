# فراگجت | FaraGadget

فروشگاه آنلاین لپ‌تاپ، موبایل و لوازم دیجیتال — پروژه‌ی نمونه‌کار، ساخته‌شده با HTML، CSS و جاوااسکریپت خالص (بدون فریم‌ورک)، با دیتابیس Firebase.

> 💡 **اگه Firebase در دسترس نباشه چی؟** سایت به‌صورت خودکار از فایل محلی `data/products.json` استفاده می‌کنه و کامل کار می‌کنه (جزئیات تو بخش «لایه‌ی دیتا و fallback»).

---

## درباره‌ی پروژه

فراگجت یک فروشگاه اینترنتی گجت و کالای دیجیتال است که تمرکز اصلیش روی پیاده‌سازی منطق واقعی فرانت‌اند بدون تکیه بر فریم‌ورک است: مدیریت state سبد خرید، اتصال به یک دیتابیس واقعی (Firebase)، فیلتر و جستجوی محصولات، و انتخاب تنوع محصول (رنگ/ظرفیت) با محاسبه‌ی قیمت.

هدف این پروژه نشان‌دادن این بود که مفاهیمی که فریم‌ورک‌های مدرن زیر پوشش خودشون مدیریت می‌کنن (مثل state و رندر مجدد UI)، وقتی با جاوااسکریپت خالص و دستی پیاده بشن، چقدر درک عمیق‌تری از خود مفاهیم می‌دن.

## امکانات

- نمایش لیست محصولات با دیتای واقعی از Firebase (Realtime Database)، با fallback خودکار به JSON محلی وقتی Firebase در دسترس نیست
- صفحه‌ی جزئیات محصول با گالری تصاویر، تب توضیحات/نظرات، و انتخاب تنوع (رنگ، ظرفیت) با محاسبه‌ی زنده‌ی قیمت
- سبد خرید پایدار (با localStorage) که با رفرش صفحه از بین نمی‌رود
- جستجو، فیلتر بر اساس دسته/برند (به‌صورت داینامیک از دیتای واقعی)/قیمت، مرتب‌سازی و صفحه‌بندی («نمایش محصولات بیشتر»)
- حالت روشن/تاریک با انتخاب دستی کاربر (ماندگار بین بازدیدها، بدون فلش رنگ موقع لود)
- طراحی کاملاً ریسپانسیو با منوی کشویی موبایل، برای موبایل و دسکتاپ
- هیروی صفحه‌ی اصلی که از خود دیتا ساخته می‌شود (محصولِ دارای `featured: true`، وگرنه بیشترین تخفیفِ موجود) و به صفحه‌ی جزئیات همان محصول لینک دارد؛ با افکت سه‌بعدیِ کج‌شدن با موس و انیمیشن‌های ورود پلکانی
- طراحی واکنش‌گرا برای موبایل و دسکتاپ: کارت‌های دو‌ستونه و فشرده در موبایل، فیلترهای تاشو، منوی همبرگری فقط زیر ۹۰۰ پیکسل و تم تاریک با تضاد رنگی مناسب
- اسکلتون لودینگ (Skeleton Loading) در صفحات دریافت محصولات
- بارگذاری پویا (Dynamic Import) فقط برای ماژول صفحه‌ی جاری
- اعتبارسنجی ساختار داده‌ی سبد خرید و ورودی‌های تعداد/قیمت پیش از ذخیره‌سازی
- دسترس‌پذیری: لینک پرش به محتوا، aria-labelها، محدودسازی فوکوس منوی موبایل، Escape و احترام به prefers-reduced-motion
- رابط کاربری فارسی (RTL)

## تکنولوژی‌های استفاده‌شده

| بخش | تکنولوژی |
|---|---|
| ساختار | HTML5 معنایی (Semantic) |
| استایل | CSS3 خالص (بدون فریم‌ورک)، با CSS Custom Properties برای تم‌بندی (روشن/تاریک) |
| منطق | جاوااسکریپت خالص (ES Modules) |
| دیتابیس | Firebase (Realtime Database) + `data/products.json` به‌عنوان fallback |
| ذخیره‌سازی محلی | localStorage (سبد خرید + تنظیم تم) |
| فونت | Estedad (تیترها) / Vazirmatn (متن بدنه) |
| تست | Vitest (filters.js، cart.js، render.js، api.js و اعتبارسنجی دیتا) |

## لایه‌ی دیتا و fallback

همه‌ی دسترسی به دیتا از `js/modules/api.js` می‌گذره؛ صفحه‌ها فقط `getAllProducts()` / `getProductById()` رو صدا می‌زنن و نمی‌دونن دیتا از کجا اومده.

1. **اول Realtime Database** — SDK مخصوص Realtime Database فقط هنگام نیاز و با `import()` پویا لود می‌شود. برنامه داده‌ها را از مسیر `/products` می‌خواند؛ ساختار فعلی می‌تواند آرایه یا آبجکتِ دارای کلیدهای رکورد باشد.
2. **Fallback محلی** — اگر اتصال/دسترسی دیتابیس خطا بدهد یا از ۸ ثانیه بیشتر طول بکشد، منبع محلی `data/products.json` استفاده می‌شود. Timeout انتظار برنامه را محدود می‌کند، اما الزاماً درخواست شبکه را لغو نمی‌کند.
3. **کش پنج‌دقیقه‌ای** — فهرست محصولات در `sessionStorage` ذخیره می‌شود؛ کش خراب، منقضی یا متعلق به منبع ناسازگار نادیده گرفته می‌شود.
4. **حافظه‌ی موقت منبع** — بعد از شکست اتصال، در حالت `auto` فقط تا پایان اجرای فعلی صفحه از تلاش‌های تکراری جلوگیری می‌شود. با Refresh اتصال دوباره امتحان می‌شود.

> در حال حاضر Realtime Database منبع اصلی است. فایل `data/products.json` فقط fallback اضطراری باقی می‌ماند؛ تعداد و محتوای محصولات Firebase را می‌توان بعداً بدون تغییر کد به ۱۰ محصول گسترش داد.

با تغییر ثابت `DATA_SOURCE` بالای `api.js` می‌شه منبع رو اجباری کرد: `"auto"` (پیش‌فرض)، `"local"` (فقط JSON) یا `"realtime-database"` (فقط دیتابیس آنلاین، برای دیباگ).

## راه‌اندازی محلی

> Firebase اختیاری است: اگر اتصال برقرار نشود، سایت از `data/products.json` استفاده می‌کند.

1. در کنسول Firebase، **Realtime Database** را فعال کنید.
2. مقدار `databaseURL` و تنظیمات اپ وب را در `js/config/firebase-config.js` بررسی کنید.
3. داده‌های محصولات را در مسیر `/products` قرار دهید. هر محصول باید فیلد `id` متنی داشته باشد؛ در ساختار فعلی، محصولات به شکل آرایه ذخیره شده‌اند.
4. پروژه فریم‌ورک یا build step ندارد؛ کافیست فایل‌ها را با یک سرور محلی ساده باز کنید (مثلاً افزونه‌ی Live Server در VS Code)، چون ماژول‌های ES از پروتکل `file://` مستقیم اجرا نمی‌شوند.

نمونه‌ی ساختار مسیر `/products`:

### مدل امنیتی و محدودیت‌های نسخه‌ی نمایشی

- سبد خرید در مرورگر نگهداری می‌شود و اطلاعات آن قابل دستکاری است؛ قیمت و موجودی LocalStorage هرگز نباید مبنای پرداخت واقعی باشند. Backend باید هنگام ثبت سفارش قیمت و موجودی را دوباره از منبع معتبر بررسی کند.
- دکمه‌ی پرداخت به درگاه واقعی متصل نیست. کد نمایشی `FARA10` فقط شناسایی می‌شود و در این نسخه تخفیف واقعی روی مبلغ اعمال نمی‌کند.
- محصول Hero صفحه‌ی اصلی یک آیتم نمایشی مستقل است و موجودی محدود نمایشی دارد؛ از دیتابیس محصولات خوانده نمی‌شود.

مقادیر داخل `js/config/firebase-config.js` (`apiKey` و بقیه) برای یک اپ وب Firebase عمومی و بی‌خطر هستند — این‌ها شناسه‌ی پروژه‌اند، نه رمز عبور. امنیت واقعی از طریق **Realtime Database Security Rules** تأمین می‌شود، نه با مخفی‌کردن این config.

> ⚠️ Rules پیش‌فرضِ «Test mode» بعد از ۳۰ روز منقضی میشن و خواندن‌ها با `permission-denied` رد میشن. جایگزینشون کنید.

فایل [`database.rules.json`](./database.rules.json) قوانین پیشنهادی را نگه می‌دارد: خواندن عمومی روی `products` (چون خود فروشگاه به آن نیاز دارد) و **بدون نوشتن عمومی** از سمت کلاینت. محتوای این فایل را در کنسول Firebase، بخش Realtime Database → Rules جایگزین و Publish کنید. تا وقتی پنل ادمین (نقشه‌ی راه) ساخته نشده، هیچ نوشتنی نباید از مرورگر مجاز باشد.

## چک‌لیست استقرار عمومی

- بعد از مشخص‌شدن دامنه‌ی نهایی، برای هر صفحه `rel="canonical"` و آدرس مطلق `og:image` تنظیم شود؛ دامنه‌ای در سورس حدس زده یا hard-code نشده است.
- در صفحه‌ی محصول، عنوان و توضیحات متا و تصویر Open Graph متناسب با محصول انتخاب‌شده به‌روزرسانی می‌شوند.
- قوانین `database.rules.json` باید در کنسول Firebase → Realtime Database → Rules منتشر شوند؛ وجود فایل در مخزن به‌تنهایی قوانین پروژه‌ی آنلاین را تغییر نمی‌دهد.
- پیش از معرفی به‌عنوان فروشگاه عملیاتی، Backend سفارش، اعتبارسنجی سمت سرور، درگاه پرداخت و منبع واقعی موجودی لازم است.

## تست‌ها

مجموعه‌ی تست شامل ۶۵ سناریو است و با [Vitest](https://vitest.dev) اجرا می‌شود: منطق فیلتر/جستجو/مرتب‌سازی (`filters.js`)، منطق و محاسبات سبد خرید و ورودی‌های نامعتبر (`cart.js`)، اعتبارسنجی LocalStorage (`storage.js`)، فرمت‌کننده‌ها و ایمن‌سازی HTML (`render.js`)، لایه‌ی دیتا با منبع محلی (`api.js`)، و اعتبارسنجی خودِ `data/products.json` (یکتایی id، فیلدهای لازم، وجود فایل عکس‌ها).

```bash
npm ci
npm test
npm run lint
npm run validate
```

## ابزارهای توسعه

`npm run validate` بدون وابستگی اضافه، syntax فایل‌های JavaScript، مسیر importهای نسبی، شناسه‌های محصولات، فایل تصاویر و نقطه‌ی ورود چهار صفحه را بررسی می‌کند.

`package.json` شامل [Prettier](https://prettier.io) (فرمت‌بندی یکدست کد) و [ESLint](https://eslint.org) (پیکربندی پایه برای JavaScript مرورگر) به‌صورت dev dependency است — هیچ‌کدام روی خروجی نهایی یا رفتار سایت اثر نمی‌گذارند، فقط ابزار توسعه‌ی محلی‌اند.

```bash
npm run format   # اجرای Prettier روی کل پروژه
npm run lint      # اجرای ESLint
```

## عیب‌یابی اتصال Firebase در شبکه‌های محدود

در بعضی شبکه‌ها ممکن است دامنه‌های Firebase و Google APIs در دسترس نباشند. در این حالت فروشگاه به‌صورت خودکار از فایل محلی `data/products.json` استفاده می‌کند و رابط کاربری همچنان قابل استفاده می‌ماند.

- اگر شبکه شما دسترسی مستقیم به Firebase ندارد، در صورت مجاز بودن از VPN یا شبکه‌ای استفاده کنید که دسترسی لازم را فراهم می‌کند.
- اگر VPN را بعد از بازکردن سایت روشن کردید، فقط صفحه را Refresh کنید؛ نیازی به بستن مرورگر، VS Code یا Live Server نیست.
- در هر بار بارگذاری کامل صفحه، برنامه دوباره اتصال Realtime Database را امتحان می‌کند. شکست قبلی اتصال فقط تا پایان همان اجرای صفحه در حافظه نگهداری می‌شود و در `sessionStorage` ذخیره نمی‌شود.
- در حالت `auto`، اگر مسیر `/products` در Realtime Database خالی باشد یا اتصال ناموفق شود، برنامه از `data/products.json` استفاده می‌کند.
- اگر پس از Refresh همچنان داده محلی نمایش داده شد، در DevTools بخش Network درخواست‌های `gstatic.com` و `faragadget-b4734-default-rtdb.firebaseio.com` را بررسی کنید و مطمئن شوید VPN واقعاً ترافیک مرورگر را عبور می‌دهد.

> دسترسی به Firebase به سیاست شبکه، تنظیمات VPN، DNS و فایروال بستگی دارد؛ بنابراین نمی‌توان تضمین کرد که همه VPNها یا همه شبکه‌ها به Firebase متصل شوند.
